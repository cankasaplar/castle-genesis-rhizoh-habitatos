# Rhizoh Invitation Study v0 — Research Dataset Specification

**Status:** DRAFT · `RESEARCH-ONLY`  
**Ethics frame:** Closed cohort · invite-only · no named celebrity dependencies  
**Spine:** Observation ≠ Execution

Participants are **research observers**, not production users. Invite tokens are opaque cohort handles — not personal identifiers.

---

## 1. Purpose

Define what to measure when invited guests (researchers, investors, explorers) enter Rhizoh under legal hold, so findings can support:

- Workshop / position / architecture papers
- Honest product iteration (perception, onboarding, map UX)
- **Not** engagement optimization or dark-pattern tuning

---

## 2. Cohort model

Three perception lenses (same system, different framing):

| Cohort label (internal) | Perception mode | Stress class (token) | Intent |
|-------------------------|-----------------|----------------------|--------|
| Explorers | `explorer` | `systems_engineer` | Experience-first map/chat discovery |
| Researchers | `research` | `human_explorer` | Causal graph + epistemic subject panels |
| Signal observers | `signal` | `invariant_keeper` | Infrastructure / pipeline observation |

**Token rule:** `cohortId` in URL must be **opaque** (`mx2401`, `mx26us`) — no role words (`yatirimci`, `investor`) in public links.

---

## 3. Metrics (v0)

| Metric ID | Description | Source (v0) | PII |
|-----------|-------------|-------------|-----|
| `invite_issued` | Invites generated by founder ops | `inviteOps.generate()` log / ops sheet | No |
| `invite_cohort` | Opaque cohort id from token | URL token parse | No |
| `invite_proceed` | User passed invite CTA | `rhizoh:invite-proceed-v0` / sessionStorage | No |
| `first_session_duration_ms` | Time from proceed → session end or 30m cap | Client observability export | No |
| `return_within_7d` | Second session within 7 days | Anonymized session key | Pseudonymous |
| `map_opened` | World tab / map surface entered | `worldObservation` ingress | No |
| `map_interaction_count` | Pin fly-to, layer toggle, camera feedback | `rhizoh.map_camera_feedback.v0` events | No |
| `castle_placement_attempt` | User uttered castle intent or opened gate | Local command handler / gate open | No |
| `observer_chat_turns` | Rhizoh conversation turns (count only) | Turn resolver / gateway trace | No |
| `voice_session_started` | STT/TTS path armed | Voice adapter boot events | No |

### 3.1 Explicitly excluded (v0)

- Real names, email, phone in dataset
- Raw chat transcript in shared research export (unless separate consent study)
- Precise GPS coordinates in aggregate publish (bucket to region or omit)
- Named simulation profiles (Nisa, Eren, etc.) as data labels

## 5. Collection posture (honest baseline)

| Capability | Today | Next |
|------------|-------|------|
| Per-invite cohort attribution | Yes (opaque token) | — |
| Centralized analytics dashboard | No | Optional export script |
| Automated mail-back survey | No | Founder manual follow-up |
| IRB / ethics board packet | Not filed | Required before formal publication |

**v0 recommendation:** Founder maintains a **private ops sheet** (cohort → person name) **outside** the repo. Published dataset uses only opaque `cohortId` + anonymized `recordId`.

---

## 6. Research questions

1. Do perception lenses change **time-to-map** or **chat depth**?
2. Does explorer framing reduce premature castle ritual vs signal cohort?
3. What fraction of invitees return within 7 days under legal-hold framing?
4. Is infrastructure (signal) copy associated with shorter or longer first sessions?

---

## 7. Publication tiers

| Tier | Requirement |
|------|-------------|
| Internal ops memo | 5+ sessions, founder review |
| Workshop paper | N≥15 anonymized records + methods section citing this spec |
| Full user study | Ethics review + consent form + retention policy |
